# 小说 Frontier 地图

按当前 artifact 只选择一个分支；下游答案改变读者、篇幅、媒介、原创性或 canon 时重新打开受影响分支。每个阶段的进入条件未满足时，不预问该阶段问题；同一轮内互不依赖的问题才可并列。

## 想法 / 立项（Project / Reader Contract）

- 进入条件：无（起点阶段）。
- 目标读者、阅读场景、类型承诺和核心情绪回报。
- 短篇、中篇、长篇、系列或连载；完结优先还是持续扩展。
- 每章/每卷稳定兑现什么，明确不写什么。
- 原创、授权改编、研究性参考和相似性边界。
- 完成标准：样章、首卷、全书大纲、完整正文或运营试验。

有代价的选择：连载带来持续曝光与追更压力，但牺牲完结节奏和一次性结构；完结优先反之。先问承诺再问表达手段。
未知 → proof：“这个想法读者会不会追”是 hypothesis，转 500–1500 字 premise pitch 或单章 proof slice，不靠追问下结论。

## 人物（Premise / World / Character）

- 进入条件：读者承诺与完成标准已 `decided` 或可安全 `provisional`。
- 主角追求、主动选择、失败代价、内外冲突和不可逆后果。
- 世界规则如何制造限制、机会和不对称，而不只是设定展示。
- 反作用力、关系张力、秘密、知识边界和人物改变方向。
- 主题通过哪些选择和后果被证明。

有代价的选择：主角早期不可逆失败换来长期代价感，但压低开局爽感；受保护的主角开局顺但后期难有真实压力。
未知 → proof：“人物是否鲜活、动机是否可信”转两个 300–600 字对立场景试写（同一人物在压力下的两种反应），不问用户“你觉得他鲜不鲜活”。

## 结构（Length / Volume / Serial Engine）

- 进入条件：篇幅形态已定；章节细节属于下一阶段，不在本轮预问。
- 分卷功能、阶段目标、升级曲线、伏笔回收窗口和终局承诺。
- 更新频率、库存与反馈可以影响哪些未来分支。
- 可扩写结构与灌水的停止线。

有代价的选择：前期密集伏笔换取长线回收，但前三章理解成本上升；单卷自洽优先则长线纵深受限。
未知 → proof：“这个升级曲线撑不撑得起 100 万字”转首卷大纲 + 前 3 章 proof slice 验证钩子密度。

## 章节（Chapter Engine）

- 进入条件：结构阶段目标已定。
- 章节状态变化、信息增量、人物推进和章尾承诺。
- 每章至少一个不可交换的因果贡献；可删章节要能识别。
- 章内节奏：场景切换数、冲突层次、留白位置。

有代价的选择：每章双钩子提高追更但推高写作成本和注水风险；单钩子稳定但断更损失更大。
未知 → proof：“章尾钩子是否抓人”转同章两种章尾（悬念式/情绪式）A/B 试写。

## 场景（POV / Voice / Scene）

- 进入条件：视角与叙述距离的相关上游已定。
- 视角、人称、时态、叙述距离、信息限制和切换规则。
- 叙述声音、人物对白、禁写和保留项。
- 场景目标、阻力、转折、后果、感官锚点和对话功能。
- 说明性信息由冲突、行动、观察还是叙述承担。

有代价的选择：贴身限知视角沉浸感强但封锁信息调度；全知视角调度自由但牺牲悬念与代入。
未知 → proof：“文风是否有辨识度、叙述是否自然”属于 hypothesis，转为同一场景两种声音的短试写或读者小样测试，不靠语言讨论裁决。

## 成稿（Drafting）

- 进入条件：场景层问题收束，进入实际产出正文。
- 产出边界：哪些章节/场景进入本轮成稿，单轮上限。
- 草稿地位：candidate，不因写出即 accepted。
- 与 writer 的串行交接见 `creative-grilling/references/writer-handoff.md`；访谈不代写正文。

有代价的选择：先粗后改保产能但中期质量风险积累；逐章精修质量稳但节奏拖长、后期间改成本高。
未知 → proof：“哪种工作流适合本书”转一个 3 章窗口的两种方式对比试产。

## 修订（Revision / Review / Adaptation）

- 进入条件：存在已产出草稿或外部反馈。
- 当前缺陷是结构、人物、连续性、节奏、对白、叙述自然度还是平台适配。
- 哪些正文和设定已 accepted，哪些只是 candidate。
- 反馈来源、证据强度、可归因缺陷和单轮修订边界。
- 改编不可牺牲承诺、删改边界、目标媒介结构和 rights gate。

有代价的选择：大改结构换取长线成立，但推翻已 accepted 设定需重开下游；表层润色保进度但留存问题遗留。
未知 → proof：“读者流失是否因节奏”转留存数据 + 对应章节 proof 重写对照，不凭单条评论定论。

## 中途进入（恢复 / 接手已有项目）

- 读取 owner 当前版本（binding 或项目 projection）的 accepted canon 与决定；只访谈 `unsettled`/`reopened` 节点，不重问仍有效决定。
- 区分“作者已决定”与“Agent 上次建议”；建议需重新确认才可升级为决定。
- 上游（承诺/人物核心）改动时，按 `creative-grilling/references/frontier-protocol.md` 重开受影响分支并暂停在途 writer 交接。
- 无 owner projection 的散稿：先做一次现状盘点访谈（缺陷归类 + accepted 边界），再进入修订分支。
