# 编辑模式与场景预设

强度决定语言改多少，范围决定允许动到哪里。两者必须分开判断。

## 任务模式

| Task | 适用请求 | 默认交付 |
| --- | --- | --- |
| `diagnose` | “哪里像 AI”“先审一下” | 问题、证据、豁免、幅度建议和短示例 |
| `rewrite` | 已有文本需要改写、润色或翻译后校准 | 改写稿；必要时附变更说明 |
| `final-pass` | 稿件基本完成，只需出版前清理 | 终稿和未解决的事实/取舍项 |
| `voice-calibration` | 用户提供多个样稿或 style bible | 可观察 voice profile 和校准稿 |

## 强度

- `light`：只处理明显僵硬、助手残留、重复和局部空话，不重排段落。
- `standard`：允许重写弱句、合并重复、修复局部段落和过渡。默认。
- `aggressive`：允许重建开头、段落和节奏，但不得改变核心论证、事实或作者立场。只有用户明确要求或原稿结构失效时使用。

## 范围

- `local`：尽量保留句子和段落边界，适合审批、翻译、技术和长度受限文本。
- `bounded`：可删除、合并和修复相邻段落，但保留论证顺序。默认。
- `structural`：允许重排或重建章节。必须由用户明确要求，或在交付前说明结构性必要性。

## 场景预设

| Scene | 默认 | 重点保护 | 常见修复 |
| --- | --- | --- | --- |
| 聊天、邮件 | `standard + bounded` | 真实关系、礼貌程度、行动事项 | 删除客服腔和无关寒暄 |
| 公众号、Newsletter、公开文章 | `standard + bounded` | 观点、来源、读者承诺 | 修复重复段落、假升华和节奏整齐 |
| 小红书、短视频、平台内容 | `standard + bounded` | 用户真实经历、平台目的、合规边界 | 去掉伪口语和万能互动句，保留可验证细节 |
| 技术文档、教程、周报 | `light + local` | 命令、版本、术语、顺序、责任 | 删除元话语和空泛评价，保留必要重复 |
| 法律、政策、事故、审批 | `light + local` | 定义、义务、禁止、条件、证据、归因 | 只做清晰度修复，不追求句式多样 |
| 学术、研究 | `light + local` | 引文、来源、限定、置信度 | 清理模糊归因，不补造引用或口语人格 |
| 产品、营销 | `standard + bounded` | 已证实卖点、限制和适用人群 | 用事实和后果替换空泛褒义词 |
| 小说、散文、剧本 | 由创作 worker 决定 | 角色声部、叙事视角、节奏装置 | 仅修复与项目风格冲突的生成模板 |

## 声音证据优先级

1. 当前项目批准的 style bible 或 voice profile；
2. 用户明确指定为自己的多个样稿；
3. 当前原稿中稳定且适合场景的习惯；
4. 中性、清楚、符合渠道的默认表达。

样稿相互冲突时，只选与当前渠道相关的特征。不要通过姓名、身份标签或私人属性猜测声音。

## 长文处理

长文先建立段落编号和保真清单，再分轮处理：

1. 全文通读，识别论证和声音；
2. 按章节做局部诊断和编辑；
3. 全文复检重复、转场、术语和节奏；
4. 对照原文检查事实与责任。

不要因为篇幅长就默认扩展权限、并行分派或升级到结构性重写。
