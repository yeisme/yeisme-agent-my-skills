# Yeisme 代码品味

先读最近项目规则、现有代码和实际调用路径。当前请求、正确性和维护边界优先。复用现有组件、库、测试与合同；最小实现与标准库优先的细节沿用 ponytail，不再建立另一套重复规则。

品味以有适用范围的决策和正反例表达。例如仅有一个调用点时保持直达的函数调用；实际存在多个消费者和稳定语义后才提炼公共抽象。保留必要错误处理、权限与验证。

用户认可的具体取舍可以成为偏好候选，单次页面反馈不扩展为全局规则。代码风格与视觉风格分别选择。用 Taste 的 preference 草稿保存适用范围和用户证据，确认后复用；不把风格变成扫描分数。
