# 中文小说社媒衍生矩阵

## 使用时机

当用户要把小说章节、梗概、项目圣经或人物设定转成小红书、公众号、短视频等社媒引流内容时读取本文件。先做选题诊断、平台角度映射和剧透边界，再交给具体平台写手产出成品。本文件与全媒介改编矩阵互补：改编矩阵跨"媒介形态"，本文件跨"营销/宣发平台"。

## 选题诊断表

把原作核心卖点映射到每个平台最匹配的角度。每条选题绑定原作证据，不靠通用人设梗。

| 核心卖点（来自分析拆解） | 小红书角度 | 公众号角度 | 短视频角度 | 剧透层级 |
| --- | --- | --- | --- | --- |
| 高概念反转（一句话卖点） | 反差钩子 / 反转名场面切片 | 类型解读 + 行业视角 | 开篇 3 秒反转 + 解谜 | 仅暗示，不揭 payoff |
| 人物关系拉扯 | CP 向情绪卡 / 人物弧线复盘 | 关系结构拆解长文 | 高光对白 + 关系转折 | 拉扯阶段可点，结局保留 |
| 世界观奇观 | 设定图卡 / 名场面视觉化 | 世界观笔记 + 类型科普 | 设定展示 + 沉浸旁白 | 设定可展，核心秘密保留 |
| 主题命题 | 读者共鸣金句 / 共情卡片 | 议题评论 / 行业反思 | 痛点场景演绎 + 金句收尾 | 主题可说，结局代价保留 |
| 名场面 | 名场面切片 + 名场面还原 | 名场面结构复盘 | 名场面还原 + 二创引导 | 视读者进度分集剧透 |

## 剧透边界矩阵

不同连载状态和平台对剧透容忍度不同。架构阶段必须为每个选题打剧透标签，避免提前杀死连载悬念。

| 连载状态 | 小红书可揭露 | 公众号可揭露 | 短视频可揭露 |
| --- | --- | --- | --- |
| 连载中（已发 N 章） | 截止 N 章已知信息；不得暗示后续反转 | 同左；可在结尾留悬念，不揭后续 | 同左；钩子用已揭露冲突，不剧透未来章节 |
| 卷末/季末 | 当卷结局可点，下一卷伏笔保留 | 当卷可复盘，跨卷秘密保留 | 当卷高光可还原，跨卷悬念保留 |
| 完结后 | 全文可讨论，但仍有"新读者阅读体验"保护带 | 可深度复盘，仍标记 spoilers | 可二创名场面，仍标注 spoiler 区分 |

引用作者侧台账控制边界（本架构不重新发明台账）：
- `chinese-novel-diagram-templates.md` 里的知识边界图：哪些信息已对读者公开、哪些仍在伏笔期。
- `chinese-novel-diagram-templates.md` 里的伏笔回收图：哪些 payoff 还未兑现，社媒不得提前剧透。

每个选题必须标注 `spoiler_level`：`hint`（仅暗示存在）、`arc_setup`（可聊铺垫阶段）、`payoff_safe`（payoff 已被连载进度覆盖，可全展）、`locked`（伏笔未兑现，禁用）。

## 平台内容包模板

### 小红书内容包

```markdown
- 核心选题：
- 绑定原作卖点：
- 角度（反差/清单/经历/身份+场景）：
- lifecycle_stage: topic | brief | draft
- reader_promise: 读者点开后能得到什么，不得脱离原作卖点
- structure_type: 名场面切片 | 人物关系复盘 | 世界观设定图卡 | 主题金句 | 连载追更引导
- constraints: 连载进度、不可剧透信息、不可伪造体验、是否允许导流
- 标题组（3 条候选，套用 xhs-content-playbook 公式）：
  1.
  2.
  3.
- 正文结构：开场场景冲突 → 经历/方法/证据 → 可收藏总结 + 评论钩子
- 图卡规划：封面 / 痛点 / 核心观点 / 步骤 / 案例 / 清单 / 误区 / 行动 / 总结（按 3/6/9 页取舍）
- 名场面切片来源（章节 + 引文范围）：
- spoiler_level：
- risk_flags: 剧透越界 / 泛人设套壳 / 引文未标章节 / 硬广导流 / 读者承诺与正文不一致
- 不写成品，handoff 到 xhs-note-writer。
```

小说到小红书的 handoff 默认先交给 `xhs-orchestrator` 做生命周期阶段控制；只有当 brief、素材证据、结构和约束都完整时，才直接交给 `xhs-note-writer` 起草正文。

## handoff 字段

每个平台内容包必须携带以下字段，让下游写手无需回读原作即可起稿：

```markdown
- source_skill: chinese-novel-content-spinoff-architect
- target_skill: xhs-orchestrator | xhs-note-writer | wechat-article-writer | short-video-scriptwriter
- lifecycle_stage: topic | brief | draft | optimize | review
- task_brief: 本次社媒内容的平台、选题、角度、目标读者
- source_material: 章节/梗概/项目圣经引用范围 + 必读 references
- reader_promise: 读者看到这条内容能得到的情绪、信息或行动价值
- structure_type: 反差钩子 / 名场面切片 / 人物关系复盘 / 主题金句 / 设定图卡 / 短视频钩子
- constraints: 剧透边界、平台边界、不可伪造字段、是否允许导流
- spinoff_assets:
    - 选题
    - 绑定卖点
    - 角度
    - spoiler_level
    - 名场面引用
    - 平台内容包模板（已填）
- continuity_delta: 本次衍生是否引入对外宣发口径变化（如新标签、新读者入口）
- risk_flags: 剧透越界 / 卖点未绑定 / 引文超出原作范围 / 平台禁区
- handoff: 交给哪个具体写手 + 需要读取哪些 reference
```

## 交接检查

- 每个选题是否绑定原作卖点（不接受泛泛人设梗）。
- 剧透边界是否按连载状态 + 平台分级，未提前覆盖未兑现伏笔。
- 引文范围是否标注章节，避免写手凭印象发挥。
- handoff 是否指向具体平台 skill，并标注需要读取的 reference。
- 小红书方向是否标明 lifecycle_stage、reader_promise、structure_type、constraints 和 risk_flags，避免下游从错误阶段起草。
- 是否规避平台禁区（小红书导流硬广、公众号违规选题、短视频敏感词等留给下游写手标注，架构层只标风险）。
