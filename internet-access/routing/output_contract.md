# 输出契约

## 目的

让互联网信息获取任务的最终回答稳定、可审计、不过度冗长。

## 通用要求

所有依赖互联网的回答都应包含：

- 结论或结果。
- 来源 URL 或来源名称。
- 关键限制或不确定性。
- 如果涉及高变动信息，说明时效性。

## `lookup` 输出

```markdown
**答案**：[直接答案]

**来源**：[URL 或结构化来源]
```

如果是版本/状态：

```markdown
**答案**：[当前版本/状态]
**更新时间**：[来源中的更新时间，如果有]
**来源**：[URL]
```

## `research` 输出

```markdown
**摘要**
[3-5 句话]

**发现**
- [发现]（来源）
- [发现]（来源）

**限制**
- [信息缺口、过时风险或冲突]

**来源**
- [标题/域名] - [URL]
```

## `deep-research` 输出

```markdown
**研究问题**
[要回答的问题和边界]

**方法**
- 查询批次：[数量]
- 候选来源：[数量]
- 去重后来源：[数量]
- 纳入样本：[数量]
- 排除规则：[规则]

**分类统计**
| 类别 | 数量 | 代表样本 |
| --- | ---: | --- |
| [category] | [n] | [source] |

**关键发现**
- [发现]（证据/样本）

**证据矩阵**
| 样本 | 类别 | 关键字段 | 来源 |
| --- | --- | --- | --- |
| [name] | [category] | [fields] | [URL] |

**限制**
- [覆盖率、搜索偏差、访问限制、时间范围]
```

如果用户要求 200/300 个实例，最终回答可以给分类统计和代表样本，但必须说明完整样本表保存在哪里，或分批输出。

如果完整样本过大：

- 用户明确要求生成文件时，按用户指定路径保存。
- 用户没有指定路径时，不默认创建文件；先给出分类统计和代表样本，并说明可继续输出完整台账。
- 如果已经创建文件，必须说明路径、记录数和字段。

## `verify` 输出

```markdown
**结论**：[成立 / 不成立 / 部分成立 / 证据不足]

**依据**
- [支持证据]（来源）
- [反向或冲突证据]（来源）

**置信度**：[高 / 中 / 低]
**注意事项**：[时效性、范围或定义问题]
```

## `extract` 输出

```markdown
**抽取结果**
| 字段 | 值 | 来源 |
| --- | --- | --- |
| [field] | [value] | [URL/API/CLI] |

**缺失字段**
- [无法获取的字段及原因]
```

## `interact` 输出

```markdown
**执行摘要**
- 工具：[agent-browser / browser-use / Playwright]
- 最终 URL：[URL]
- 完成：[成功操作]
- 阻塞：[权限、登录、验证码、付费或其它限制]

**证据**
- 截图：[路径]
- 下载：[路径]
- 其它：[console/errors/network，如有]
```

## `automate` 输出

```markdown
**自动化建议**
- 推荐方式：[项目已有命令 / npx playwright / agent-browser 探索后固化]
- 原因：[为什么需要可重复自动化]
- 风险：[登录态、selector、速率限制、条款]
- 验证命令：[可直接运行的命令]
```

## 失败或阻塞输出

```markdown
**结果**：未能完成。

**原因**：[工具缺失 / 权限不足 / 需要登录 / 页面阻塞 / 来源不可用]

**已尝试**
- [命令或工具]

**下一步**
- [需要用户提供什么或建议的降级路径]
```
