# 测量与评分

服务器质量是实例、用途、用户网络、目标、时间和成本约束的共同结果。相同服务器对不同用途可有不同结论。

主机资源和管理机探测默认每分钟，服务器出口每五分钟；不能据此声称秒级故障定位。CPU ticks 只跨同一 boot ID 且计数器不回退时差分。PSI 用于资源停顿；CPU 型号、磁盘计数器和单次下载峰值都不足以证明长期性能。

IP/网络报告来自特定脚本和版本。ERROR、NoData、缺失字段、显示零、真正的零保持不同。重传计数没有分母时不是丢包率。CN2 标签不能直接扩展为 CN2 GIA 或双向全国优化。入口 IPv6 不决定出口一定是 IPv6。

缓存同时显示最后成功值和最后一次采集结果。资源180秒、出口探测900秒、规格七天、出口IP一天为默认 TTL；地址或身份绑定改变可提前失效。缓存有效不证明来源绝对正确，第三方风险信号须保留作用域。

原型评分的逻辑区间为 `[K, K + 100(1-C)]`，其中 C 为已覆盖指标权重、K 为已知指标贡献；不是统计置信区间。当前 `evaluate` 要求证据引用存在、时间有效、实例绑定和 context 匹配。旧合成评分的 freshness_verified/provenance_resolved=false 不能当成当前验收。

样本成功率与采集覆盖率分开。没有采集的时段标为缺测，不能填健康或失败。不足七天只做短期判断，14天且覆盖率足够可冻结基线，30天报告仍必须说明缺测和维护窗。

依据：[RFC 6349](https://www.rfc-editor.org/rfc/rfc6349)、[RFC 3393](https://www.rfc-editor.org/rfc/rfc3393)、[Linux PSI](https://www.kernel.org/doc/html/latest/accounting/psi.html)。规则与 TTL 是工程默认值，不是供应商承诺。
