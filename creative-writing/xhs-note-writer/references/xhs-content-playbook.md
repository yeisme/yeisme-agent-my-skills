# 小红书内容 playbook

## 使用时机

当小红书任务需要标题公式、正文结构、图卡页序、系列拆帖、标签策略或去 AI 味检查时读取本文件。它是平台写手的内容模板，不替代 `xhs-orchestrator` 的生命周期分派，也不替代用户真实素材。

## 选题落点

- 读者痛点：一句话写清读者正在遇到什么具体问题。
- 可信素材：列出本人经历、原始资料、案例、截图、数据来源或可引用文本；缺失时提问。
- 读者承诺：读完能得到一个判断、步骤、清单、避坑点、情绪安慰或行动建议。
- 平台角度：反差、清单、复盘、避坑、教程、名场面切片、个人经历、专业拆解，不混成泛泛鸡汤。
- 互动动作：收藏、评论、私下复盘、下一篇继续看；不承诺涨粉、收益、治疗或平台推荐。

## 标题公式

- 身份 + 场景 + 结果：`普通打工人如何把周末复盘变成求职素材`。
- 反差 + 具体问题：`我以为是拖延，其实是目标颗粒度太粗`。
- 清单 + 收藏理由：`新手做 AI 副业前先检查这 7 件事`。
- 经历 + 结论：`裸辞后我才发现，真正消耗我的不是工作量`。
- 名场面 + 情绪：`看到她转身那一刻，我才懂这段关系为什么回不去了`。
- 专业判断 + 反常识：`别急着写正文，先把这 3 个读者承诺定下来`。
- 失败复盘 + 避坑：`这次选题没爆，不是标题差，是素材证据太虚`。

标题不要只追求夸张，应保留可兑现承诺：标题里的身份、数字、结果、经历和评价必须能在正文中找到证据。

## 正文结构

开头给场景和冲突，中段给经历、方法、证据或步骤，结尾给可收藏总结和评论问题。图卡按 3/6/9 页设计：封面、痛点、核心观点、步骤、案例、清单、误区、行动、总结。

### 经历复盘

```markdown
1. 开头：具体场景 + 误判或转折。
2. 中段：发生了什么、当时怎么想、后来怎么验证。
3. 方法：提炼 3-5 个可复用动作或判断。
4. 结尾：给同类读者一个评论问题或收藏理由。
```

### 清单/教程

```markdown
1. 开头：谁适合看，解决什么问题。
2. 清单：每条包括动作、原因、适用条件和常见坑。
3. 例子：至少一个来自用户素材或可核验来源的例子。
4. 结尾：下一步检查项，不制造焦虑。
```

### 名场面/小说衍生

```markdown
1. 开头：不剧透核心 payoff 的情绪钩子。
2. 证据：章节范围、人物关系或场景冲突。
3. 观点：为什么这个名场面值得读者继续看。
4. 图卡：封面钩子、人物关系、冲突递进、金句、追更入口。
5. 边界：标注 spoiler_level，未兑现伏笔保持 locked。
```

## 图卡页序

- 3 页：封面 / 核心观点 / 行动或评论钩子。
- 6 页：封面 / 痛点 / 反差 / 方法或证据 / 案例 / 总结。
- 9 页：封面 / 场景 / 问题 / 核心观点 / 步骤 1 / 步骤 2 / 案例 / 误区 / 行动。

图卡文案要短，优先一句话一屏；长解释放正文，不塞进图卡。

## 标签与结尾

- 标签组合：1-2 个大类标签、2-4 个细分场景标签、1 个账号自有主题标签。
- 评论钩子：问读者处境、选择、补充经验或下一篇想看什么。
- 导流表达要克制，避免硬广、诱导互动、承诺收益或伪造平台反馈。

## 去 AI 味检查

- 删除“在这个快节奏时代”“不妨试试”“总之”等模板句。
- 把抽象判断换成具体场景、动作、限制条件和代价。
- 段落长短错落，保留口语停顿，但不刻意装随意。
- 每个强结论都要有素材、经历、案例或原文证据支撑。
