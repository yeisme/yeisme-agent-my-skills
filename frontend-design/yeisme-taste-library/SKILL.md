# Taste 知识库

先从项目需求、既有设计系统和目标媒介开始。用 Taste CLI/MCP 的 capabilities 发现实际输入，或 DSH 的模板与 Taste 页面。只有一个主要视觉方向，辅助来源补充指定维度。

来源固定 URL、revision、内容摘要与许可；地区和工作室是检索线索，可观察决策才是设计依据。原生媒介和转译媒介分开，来源审阅不等于浏览器验证。

读取卡片时区分来源规则、个人偏好和本次建议。代码品味约束实现，视觉 Taste 约束呈现；当前用户要求与项目约束优先。模板使用 frontend-taste-brief-beta，实际截图和交互证据交给 frontend-taste-review-beta。

来源更新生成候选，旧任务固定快照。用户反馈形成有范围的偏好提案。无 Registry 时允许方法简报，不声称完成编译。未安装 CLI 的远程客户端直接发现 MCP；客户端路径不是服务端路径。
